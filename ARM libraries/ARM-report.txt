LIVECODE ENGINE - ARM MACOS (APPLE SILICON) COMPILATION REPORT
================================================================

EXECUTIVE SUMMARY
-----------------
Compiling LiveCode for native ARM macOS (Apple Silicon/M1/M2/M3) requires:
1. Architecture configuration changes across all Xcode projects
2. Recompilation of 20+ third-party libraries for ARM64
3. Build system modifications (gyp/Makefile)
4. Potential assembly code updates in libraries
5. Testing and validation across all engine components

CURRENT STATE: x86_64 ONLY
The entire codebase is currently hardcoded to build for x86_64 Intel architecture.


DETAILED ANALYSIS
=================

1. BUILD SYSTEM ARCHITECTURE CONFIGURATION
------------------------------------------

Current Architecture Settings:
- All Xcode projects specify: ARCHS = x86_64
- Build configuration: config/mac.gypi lines 216, 226, 236
- Deployment target: macOS 10.9 (supports Intel only)
- SDK: macOS 12.1 SDK (includes ARM64 support in .tbd files)

Files Requiring Architecture Changes:
- config/mac.gypi (3 locations: Debug, Release, Fast configurations)
- All 65+ .xcodeproj/project.pbxproj files in build-mac/
- config/arch.gypi (add ARM64 host detection)

Proposed Architecture Setting:
- Change ARCHS from 'x86_64' to 'arm64' for native ARM
- OR use 'x86_64 arm64' for Universal Binary (both architectures)
- Update MACOSX_DEPLOYMENT_TARGET to 11.0 minimum (first ARM macOS)

Total: 20+ libraries requiring ARM64 compilation


3. ASSEMBLY CODE REQUIRING ATTENTION
-------------------------------------

Libraries with Architecture-Specific Assembly:

libffi:
- src/aarch64/sysv.S (ARM64 calling conventions)
- Multiple ARM assembly files for 32-bit ARM
- Critical for foreign function calls

libcairo:
- src/pixman-arm-neon-asm.S
- src/pixman-arm-neon-asm-bilinear.S
- src/pixman-arm-simd-asm.S
- src/pixman-arm-simd-asm-scaled.S
- ARM NEON SIMD optimizations

libopenssl:
- crypto/x86_64cpuid.s (x86_64 specific)
- Needs ARM64 equivalent assembly
- Performance-critical cryptographic operations

libskia:
- src/opts/ directory contains architecture-specific optimizations
- ARM NEON implementations available (opts_armv7_arm64_srcs)
- Needs proper build configuration selection

- Architecture detection needed


5. TOOLCHAIN CONSIDERATIONS
----------------------------

The LiveCode toolchain (gentle, reflex, lc-compile) must run during build:
- Currently compiled for x86_64
- Options:
  a) Cross-compile: Build x86_64 toolchain, use Rosetta 2 during ARM build
  b) Native: Build ARM64 toolchain first, then use for ARM engine build
  c) Universal: Build universal binary toolchain

Recommendation: Option (a) initially - use Rosetta 2 for toolchain
- Simplest approach
- Rosetta 2 performance adequate for build tools
- Later optimize with native ARM toolchain


6. ENGINE SOURCE CODE
----------------------

Good News:
- Engine source is largely architecture-agnostic C++
- No inline assembly found in engine/src/*.cpp
- Uses standard C++ and platform APIs
- Minimal architecture-specific code

Potential Issues:
- Endianness assumptions (ARM is little-endian like x86_64)
- Pointer size assumptions (both are 64-bit)
- SIMD intrinsics if any (need ARM NEON equivalents)
- Memory alignment requirements may differ

8. DEPLOYMENT TARGET CONSIDERATIONS
------------------------------------

Current: macOS 10.9 (2013)
Required for ARM: macOS 11.0 Big Sur minimum (2020)

Impact:
- First macOS version with Apple Silicon support
- May require updating deprecated API usage
- Benefits: Access to newer macOS features
- Trade-off: Drops support for older Intel Macs

Options:
- Single ARM64 build (macOS 11.0+)
- Universal Binary (macOS 11.0+ for ARM, 10.9+ for Intel)
- Separate builds for Intel and ARM

ALTERNATIVE APPROACHES
======================

1. ROSETTA 2 TRANSLATION (CURRENT STATE)
   - x86_64 build runs on ARM via Rosetta 2
   - Pros: No work required, already functional
   - Cons: ~20-30% performance penalty, not native

2. NATIVE ARM64 BUILD (RECOMMENDED)
   - Full recompilation for ARM64
   - Pros: Native performance, future-proof
   - Cons: Significant development effort

3. UNIVERSAL BINARY
   - Single binary supporting both architectures
   - Pros: Maximum compatibility
   - Cons: 2x binary size, longer build times

4. SEPARATE BUILDS
   - Maintain separate x86_64 and ARM64 builds
   - Pros: Smaller binaries, independent optimization
   - Cons: More complex distribution


TECHNICAL NOTES
===============

SDK Compatibility:
- macOS 12.1 SDK includes ARM64 support
- All system frameworks have arm64 slices in .tbd files
- SDK already supports universal binary compilation

Rosetta 2 During Build:
- x86_64 toolchain can run via Rosetta 2 during ARM build
- Allows incremental migration
- Build tools don't need native ARM initially

Library Versions:
- OpenSSL 1.1.1g (2020) - has ARM64 support
- ICU 58.2 (2017) - has ARM64 support
- All third-party libraries are ARM-compatible versions

Code Signing:
- ARM64 binaries require proper code signing
- Ad-hoc signing sufficient for development
- Distribution requires Apple Developer ID


RECOMMENDATIONS
===============

1. START WITH NATIVE ARM64 BUILD
   - Focus on single architecture initially
   - Simpler than universal binary
   - Can add x86_64 later if needed

2. BUILD LIBRARIES INCREMENTALLY
   - Start with libraries that have assembly code
   - Test each library before proceeding
   - Catch architecture issues early

3. USE ROSETTA 2 FOR TOOLCHAIN
   - Keep toolchain as x86_64 initially
   - Reduces complexity during transition
   - Optimize toolchain later

4. EXTENSIVE TESTING REQUIRED
   - ARM architecture may expose latent bugs
   - Test all major functionality areas
   - Performance validation critical

5. CONSIDER DEPLOYMENT TARGET
   - macOS 11.0 minimum for ARM support
   - Evaluate if older Intel Mac support needed
   - Universal binary if backward compatibility required


CONCLUSION
==========

Compiling LiveCode for native ARM macOS is feasible but requires:
- Systematic recompilation of 20+ third-party libraries
- Build system configuration updates across 65+ projects
- Careful handling of architecture-specific assembly code
- Comprehensive testing and validation

The work is substantial but straightforward, with no fundamental blockers.
The existing codebase is well-structured for cross-platform support.
The macOS 12.1 SDK already includes all necessary ARM64 support.

Estimated effort: 5-7 weeks for complete ARM64 native build with testing.

This document serves as a roadmap for the ARM compilation project.
